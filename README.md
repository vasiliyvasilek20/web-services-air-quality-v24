Приложение получает индекс AQI по координатам экологической зоны и сохраняет историю запросов в PostgreSQL.

## Запуск

Необходимы Docker и Docker Compose. В каталоге проекта выполните:

```sh
docker compose up --build -d --wait
```

Откройте [http://localhost:8080](http://localhost:8080).

## Компоненты

В `docker-compose.yml` объявлены четыре сервиса:

- `frontend` — веб-интерфейс на HTML/CSS/JavaScript, сервер Nginx;
- `backend` — REST API на Python, взаимодействие с PostgreSQL и сервисом AQI;
- `db` — PostgreSQL 17;
- `web-service` — локальный HTTP-сервис-эмулятор AQI по координатам.

Сервисы взаимодействуют во внутренней bridge-сети Docker Compose. `depends_on` и `healthcheck` задают порядок запуска. Именованный том `db_data` сохраняет данные между перезапусками. При первой инициализации `db/init.sql` создаёт таблицы и три начальные экологические зоны.

## Использование

1. «Загрузить зоны из БД» — получить экологические зоны и последнее сохранённое значение AQI.
2. Выбрать зону и нажать «Получить AQI и сохранить» — запросить сервис AQI и записать наблюдение в БД.
3. «Загрузить историю из БД» — показать сохранённые результаты запросов.

Также доступны создание, переименование и удаление экологической зоны. При удалении зоны её история удаляется каскадно.

## Реализация варианта

Таблица `zones` хранит название и координаты зоны. Таблица `measurements` хранит AQI, категорию, источник и время запроса.

Backend получает координаты зоны из PostgreSQL и отправляет HTTP-запрос `web-service:8001/aqi`. Сервис возвращает учебный AQI, рассчитанный детерминированно по координатам. Затем backend сохраняет результат в PostgreSQL.

Используется разрешённый заданием локальный эмулятор. **Значения синтетические и не отражают реальное качество воздуха.** Это указано в интерфейсе и источнике каждой записи. Внешние API-ключи не требуются.

## Остановка

```sh
docker compose down
```

Данные сохраняются в томе БД. Полный сброс с удалением данных: `docker compose down -v`.
